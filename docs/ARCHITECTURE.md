# Architecture

## Data flow

```text
src/config/*.ts, src/content/*.ts      (editable data, typed)
        │  validated by
        ▼
src/lib/validations/content.ts          (Zod schemas = source of truth)
        │  types inferred into
        ▼
src/types/content.ts
        │
src/lib/content.ts                      (accessors: drafts filtered here)
        │
        ▼
server components in src/components/*   (render only)
        │
        ▼
src/app/* routes, sitemap, robots, metadata
```

Schemas are enforced by `tests/unit/content.test.ts`, so bad content fails
`npm test` rather than breaking the page.

## Key decisions

- **Server components by default.** Client components exist only where the
  browser is required: `animations/neural-background.tsx` (canvas),
  `hero/role-rotator.tsx` (timer) and `layout/mobile-nav.tsx` (menu state).
  Entrance animations are CSS-only (`animations/reveal.tsx` is a server
  component). Logic that can be pure lives in `lib/particles.ts` and is unit
  tested.
- **Section registry** (`src/config/navigation.ts`). `enabled` controls both
  rendering and navigation links, and array order is the page order
  (`src/app/page.tsx` maps each id to its component). Sections not built yet are `enabled: false`.
- **Draft visibility.** `visibility: "draft"` projects are excluded by
  `getPublishedProjects()`, so they vanish from the list, `generateStaticParams`
  and the sitemap in one place.
- **Cache Components enabled** (`next.config.ts`). Dynamic params outside
  `generateStaticParams` render at request time.
- **`src/proxy.ts` for honest 404s.** With Cache Components, a project slug
  that was not pre-rendered is resolved at request time and streamed, so the
  status would be 200 before `notFound()` runs (a "soft 404"). The proxy checks
  the slug against the content file first and rewrites unknown or draft slugs
  to a path that renders `not-found.tsx` with a real 404. Verified: without the
  proxy an unknown slug returns 200.
- **No root `loading.tsx`.** It makes every page stream: the prerendered HTML
  contained only "Loading…" with the real content in a hidden block that needs
  JavaScript to appear. Without it the prerendered home page contains all its
  content inline (about 40 KB vs 244 bytes in `<main>`). Use component-level
  `Suspense` with a meaningful fallback where something genuinely loads.
- **Contact section is the one request-time part of the home page.**
  `components/sections/contact.tsx` calls `connection()` so it can read mail
  settings when the server starts instead of at build time, and
  `app/page.tsx` wraps it in its own `Suspense` so the rest of the page stays
  prerendered (route shows as "Partial Prerender").
- **Contact backend** (`src/lib/contact-handler.ts`, `contact-config.ts`,
  `rate-limit.ts`, `validations/contact.ts`; route in `app/api/contact`). The
  handler takes its dependencies as arguments (config, fetch, limiter) so unit
  tests need no network. The form is rendered only if the server has all three
  mail variables.
- **Resume check at render time** (`src/lib/resume.ts`): the button shows only
  if the file exists in `public/`.
- **Self-hosted fonts**: no network requests to Google Fonts.
- **Tailwind 4 via Turbopack loader** configured in `next.config.ts`.

## Changes from the suggested structure in the brief

| Brief                                                       | Actual                                          | Reason                                          |
| ----------------------------------------------------------- | ----------------------------------------------- | ----------------------------------------------- |
| `public/fonts/`                                             | fonts in `src/fonts/`                           | `next/font/local` bundles them from `src`       |
| `src/hooks/`, `src/services/`                               | not created                                     | Nothing needs them yet; add with first real use |
| `components/{hero,skills,experience,contact,animations,ui}` | only `layout`, `sections`, `projects`, `shared` | Created when the phase that needs them starts   |
| `next.config.ts`, `eslint.config.mjs`                       | same                                            | —                                               |
| `postcss.config.mjs`                                        | none                                            | Tailwind runs through `@tailwindcss/turbopack`  |
| `shadcn/ui`                                                 | not installed                                   | No component needs it yet                       |
| —                                                           | `src/proxy.ts`, `AGENTS.md`                     | Real 404s; `AGENTS.md` is generated by Next.js  |

## Adding a new section (pattern)

1. Add its data file in `src/content` and a Zod schema/type.
2. Add a component in `src/components/<area>/`.
3. Render it in `src/app/page.tsx` guarded by `isSectionEnabled("<id>")`.
4. Set `enabled: true` in `src/config/navigation.ts`.
5. Add unit and e2e coverage; update CHANGELOG and roadmap.
